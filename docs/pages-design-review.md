# Pages全体の設計整理

目的: 単純で共通化された実装、必要最小限のブラウザリソース、PC・スマホで見やすく操作しやすい統計画面にする。
基準コミット: 421029293509e38ab7a9434ffd3309b6a8480c21。

- [x] 長い画面に概要/一覧の切り替えを導入し、グラフと楽曲一覧へのアクセスを改善する。

## 実装方針
既存の素のES Modulesとesbuildを継続する。共通UIへ正規化したデータを渡し、取得元の違いはリードモデルで吸収する。機能を維持し、収集周期やD1/Queue/R2利用量を増やさない。StationheadとHomePanelの配信境界は維持する。

## 検証と完了条件
初期表示・各画面・全体のHTML/JS/CSS容量を比較し、不要な依存とCSS上書きが削減されること。PC/スマホの全画面で操作可能で表示崩れがないこと。関連テストと必須CIが成功すること。未確認事項は明記する。
## 実装済み（検証中）
- CSSをbase/features/layoutのレイヤーで分離し、共通レイアウトへ集約。機能別の数値列配置は維持。
- PCはサービス選択を折り返し、スマホはネイティブselect。音楽サービスは概要/一覧/プレイリストで切り替え。
- 共通の遅延CSSローダーとルートローダー。初期画面のシェル/ランタイムも遅延読み込み。
- window.fetchの全体上書きを廃止。共有取得クライアントを追加し、同時取得・失敗後の再取得・購読者単位の中断を検証。
- Stationheadタイマーを可視画面だけに限定し、古い取得結果による画面の上書きを防止。
- 資産容量レポート/予算を追加し、追跡済み生成資産を更新。CSS共有と遅延読み込みを統合。

同じソースビルド方法で比較。無圧縮の生成JS/CSSサイズであり、実ネットワーク転送量ではない。

追加ブラウザCIで390/1440pxの18ルート（36表示）の空データ表示と横幅を検証し成功。スクリーンショットでPCの横並び・スマホの選択欄を確認し、スマホの重複ナビを修正。概要/一覧/プレイリストの切り替えと可視性チェックを追加。実データのグラフ・CSV・全サブタブ・公式ライブページの目視確認は未完了。
ローカルD1テストは既存migration 011で`no such column: isrc`となり失敗。今回SQL変更はなく、Pages改修とは別の既存スキーマ問題として記録する。
