# Pages全体の設計整理

目的: 単純で共通化された実装、必要最小限のブラウザリソース、PC・スマホで見やすく操作しやすい統計画面にする。
基準コミット: 421029293509e38ab7a9434ffd3309b6a8480c21。

## 作業内容
- [ ] 現行のJS依存関係・CSS・ルート・全画面を棚卸しし、ビルド後の初期/画面別/全体容量を記録する。
- [ ] CSSの基本設定・共通部品・機能固有の責任を整理し、重複ルールと不要な上書き・!importantを削減する。
- [ ] 余白・文字・操作部品・数値・表・グラフの共通スタイルを一本化する。
- [ ] PCのサービス選択を横並び＋折り返しにし、スマホではコンパクトな選択欄にする。現在位置・キーボード操作・戻る/進むを維持する。
- [ ] 長い画面に概要/一覧の切り替えを導入し、グラフと楽曲一覧へのアクセスを改善する。
- [ ] Stationhead全チャンネルの共通画面とチャンネル別リードモデル、リーダーボード/フォローの共通表示を整理する。
- [ ] 旧実装・未使用モジュールを依存関係確認後に削除し、初期JSへの不要な取り込みを削減する。
- [ ] window.fetch全体の上書きを明示的な取得関数へ置き換え、重複取得・キャッシュ・エラー・再試行・中断処理を整理する。
- [ ] 画面切り替え時の更新・タイマー・グラフ描画を整理し、非表示画面の無駄な処理を減らす。
- [ ] CSS・JSの遅延読み込みと共有チャンク、バージョン・キャッシュ設定を見直す。
- [ ] 容量指標と予算チェックをビルドに追加し、実測値と圧縮推計を区別して比較する。
- [ ] モバイルの文字サイズ・タップ領域・表の横スクロール・長い曲名・空/エラー表示を改善する。

- [ ] 関連テストと必須CIを実行し、PR本文を完了内容・実測結果・残課題に更新する。

## 実装方針
既存の素のES Modulesとesbuildを継続する。共通UIへ正規化したデータを渡し、取得元の違いはリードモデルで吸収する。機能を維持し、収集周期やD1/Queue/R2利用量を増やさない。StationheadとHomePanelの配信境界は維持する。

## 検証と完了条件
初期表示・各画面・全体のHTML/JS/CSS容量を比較し、不要な依存とCSS上書きが削減されること。PC/スマホの全画面で操作可能で表示崩れがないこと。関連テストと必須CIが成功すること。未確認事項は明記する。
